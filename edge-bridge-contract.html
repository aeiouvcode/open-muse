Open Muse x EDGE//AI bridge contract

Both apps are static sites on aeiouvcode.github.io (same origin). Open Muse embeds EDGE//AI in a hidden frame and talks to it with postMessage. No backend, no key; the model runs on the user's device. This page documents the wire format and - when loaded with the bridge params - acts as a working echo backend so either side can be tested alone. v1

1. Frame URL

https://aeiouvcode.github.io/edge-ai/?bridge=openmuse&nonce=<random>

Open Muse generates the nonce per session and trusts only messages that echo it. Both sides check event.origin === "https://aeiouvcode.github.io".

2. Handshake (edge -> muse)

{ edgeai: "ready", nonce, models: [ { id, name, params } ] }

models lists chat-capable on-device models EDGE//AI can actually run. Sent once the frame is up.

3. Inference request (muse -> edge)

{ edgeai: "infer", id, nonce, model, stream: true|false,
  messages: [ { role: "system"|"user"|"assistant", content: "..." } ] }

4. Responses (edge -> muse)

{ edgeai: "chunk", id, text }   // accumulated text so far, 0..n times (stream mode)
{ edgeai: "done",  id, text }   // final full text
{ edgeai: "error", id, message }

5. URL-param entry (no embed)

https://aeiouvcode.github.io/edge-ai/?bridge=openmuse&prompt=<text>

Opens EDGE//AI visibly and runs the prompt - the human handoff link.

6. Echo-stub mode (this page)

Loaded with ?bridge=openmuse&nonce=..., this page speaks the contract with a deterministic echo backend, so Open Muse's bridge can be verified end-to-end before (or after) EDGE//AI ships its side.

Loaded bare - documenting only.
